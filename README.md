# SLIME Assets

SLIME 게임에서 채택한 공개 에셋의 관리 저장소다.

## 초기 관리 범위

| 디렉터리 | 대상 |
|---|---|
| `assets/tiles/` | 지면·벽·지붕 등 타일 텍스처 |
| `assets/sprites/` | 캐릭터·몬스터·오브젝트·이펙트 스프라이트와 재생 메타데이터 |
| `assets/maps/` | 게임 실행용 맵 데이터와 에셋 참조 |

관리 ID·버전·경로·해시는 `asset-registry.yaml`에서 관리한다. 프론트엔드의 지형·마을 타일과 건물 표면 이미지 및 출처 sidecar 90개를 이관했다. `assets/tiles/terrain/road/`·`assets/tiles/terrain/non-road/`·`assets/tiles/terrain/blocked/`, `assets/tiles/buildings/<재질>/`에서 관리하며 등록부에 기존 ID, 원본 커밋, 전달 경로와 SHA-256을 보존한다. 프론트엔드에는 해시로 고정한 배포용 사본만 유지한다.

## 등록 원칙

- 사용자가 채택한 에셋만 등록한다. 실험 결과나 후보는 자동 등록하지 않는다.
- 기존 관리 ID를 유지하고, 변경된 에셋은 새 버전으로 등록한다.
- 파일과 공개 가능한 출처·해시·제작 도구·라이선스 정보를 함께 관리한다.
- 내부 프롬프트·개인 경로·인증정보·비공개 기획 및 설계 자료는 포함하지 않는다.
- 모델 가중치, 생성기, 로그, 모션·리그 제작 자산, UI 이미지와 오디오는 초기 범위에서 제외한다.
- 공개 저장소라는 사실은 개별 에셋의 사용 허가를 뜻하지 않는다. 재사용 조건은 에셋별 라이선스 정보를 따른다.

## 소비 저장소와의 연결

프론트엔드는 검증된 버전 또는 커밋으로 에셋을 명시적으로 가져온다. `../slime-assets` 같은 로컬 상대 경로를 게임 런타임 의존성으로 사용하지 않는다. 기존 게임은 이관과 소비 코드 변경이 완료될 때까지 현재 에셋을 사용한다.

생성·검수·크롭은 `slime-workflow`, 렌더링·재생 코드는 `slime-frontend`, 비공개 설계 문서는 `slime-backend`에서 관리한다. 이 저장소에는 공개 가능한 게임 실행용 산출물만 전달한다.

## 맵 데이터 범위

프론트엔드는 맵 배치 데이터를 백엔드 API로 수신하며 독립된 맵 데이터 파일을 소유하지 않는다. 이번 프론트엔드 이관에는 맵 배치 파일이 없으므로 `assets/maps/`는 비어 있다. 백엔드 맵 데이터와 비공개 설계는 복제하지 않았다. 원본 출처에 없는 라이선스나 제작 도구 정보를 추정하지 않으며 기존 재사용 조건을 유지한다.

건물 타일은 마을 전용으로 분류하지 않습니다. `wood`·`stone`·`red-stone`·`marble` 재질 폴더에 파일을 바로 두며 문·지붕·벽 용도는 파일명으로 구분하고, 마을별 적용은 소비자의 맵 설정에서 선택합니다.

## 맵 원본 직접 참조

`assets/maps/`의 `city_layouts`, `field_tiles`, `field_waypoints`, `terrain`, `map_spawns`, `map_names`가 맵 원본입니다. 139개 YAML의 관리 ID·버전·출처·해시를 등록부에 보존합니다. 백엔드는 잠금 목록을 검증해 직접 읽으며, 관리도구도 같은 원본을 직접 제공합니다. 백엔드 설정 및 워크플로우 맵 JSON 사본을 중복 관리하지 않습니다.
